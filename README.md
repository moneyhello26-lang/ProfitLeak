# ProfitLeak AI

Финальное расширение локального выпуска: **Деньги и платежи** — счета и остатки,
денежные операции и переводы, платёжный календарь, прогноз кассового разрыва,
месячный бюджет и план-факт, импорт выписок CSV/XLSX по единому шаблону.
Инструкция: [деньги, платежи и файловый обмен](docs/CASH_GUIDE.md).

Готовый проект без облачных сервисов: [локальный запуск и передача](docs/LOCAL_RELEASE.md),
[текущее состояние и проверки](HANDOFF.md). Docker, Render, Neon и облачные API
для этого варианта не нужны. Данные хранятся в SQLite на компьютере.

Локальный сервис финансовой аналитики для малого бизнеса: React + TypeScript,
FastAPI и SQLite. Docker и отдельный сервер базы данных для запуска не нужны.
Интерфейс на русском и казахском, валюта KZT. Импорт CSV/XLSX, финансовый дашборд, прибыльность
товаров и детектор с доказательствами и рекомендациями уже реализованы.
Добавлены AI-советник с подключением Gemini/OpenAI и локальный экспорт PDF.
Страницы **Сравнение периодов** и **Прогнозирование** показывают динамику KPI,
товаров и расходов, прогноз на 7–90 дней и сценарии продаж/затрат. Они работают
локально и не расходуют LLM-квоту: [гайд и контрольные примеры](docs/PLANNING_GUIDE.md).
Пошаговая настройка ключа, проверка чата и решение ошибок:
[гайд LLM и советника](docs/LLM_ADVISOR_GUIDE.md).
Регистрация, вход, смена пароля и команда с ролями владельца, аналитика и
наблюдателя: [аккаунты и язык интерфейса](docs/ACCOUNTS_AND_LANGUAGE_GUIDE.md).

## Быстрый запуск

На этом компьютере зависимости подготовлены. Из корня проекта в PowerShell:

```powershell
.\start-local.ps1
```

Если PowerShell запрещает запуск локального скрипта:

```powershell
powershell -ExecutionPolicy Bypass -File .\start-local.ps1
```

Скрипт применяет миграции и запускает API с готовым интерфейсом одним процессом.
Откройте **http://127.0.0.1:5173**. API: **http://127.0.0.1:5173/docs**.
Ctrl+C останавливает приложение. SQLite выбирается независимо от старого
DATABASE_URL; файл базы — `backend/profitleak.db`. Внешний LLM и API-ключи
отключаются для этого процесса. Если отсутствует `frontend/dist`, сначала
выполните `npm.cmd --prefix frontend run build`. В архиве выпуска сборка включена.

При первом открытии зарегистрируйте свой аккаунт. Первый зарегистрированный
пользователь становится владельцем ранее созданных бизнесов; их данные сохраняются.
Дальнейшие пользователи получают доступ к бизнесу через **Аккаунт и команда**.
Переключатель **RU / ҚАЗ** доступен до и после входа. Общих логинов и паролей нет.

## Установка на другом компьютере

Нужны Python 3.11+ и Node.js 22.18+. Команды из корня проекта:

```powershell
python -m venv backend/.venv
backend/.venv/Scripts/python.exe -m pip install -e './backend[dev]'
npm.cmd --prefix frontend ci
npm.cmd --prefix frontend run build
.\start-local.ps1
```

`.env` необязателен: SQLite настроена по умолчанию. Для изменения параметров:

```powershell
Copy-Item .env.example .env
```

Относительный путь SQLite разрешается относительно корня проекта, поэтому база
не меняется при запуске из другой рабочей папки. Файл БД и `.env` исключены из Git.

Запуск для разработки вручную, в двух терминалах (или прежний `start.ps1`):

```powershell
backend/.venv/Scripts/python.exe -m alembic -c backend/alembic.ini upgrade head
backend/.venv/Scripts/python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1
```

```powershell
npm.cmd --prefix frontend run dev
```

Миграции выполняются явно; запуск FastAPI сам по себе таблицы не создаёт. Vite
проксирует `/api` на backend. Для production-хостинга нужна такая же настройка
прокси; `vite preview` сам по себе её не предоставляет.

## Демонстрация

1. После входа нажмите **Открыть демо-бизнес**: загрузятся 90 дней синтетических данных кафе
   Тараза, с 04.07.2026 по 01.10.2026, в отдельный бизнес текущего аккаунта.
   Повторная загрузка не дублирует строки.
2. Проверьте выручку **5 454 000 ₸**, COGS **2 475 000 ₸**, валовую прибыль
   **2 979 000 ₸** и операционную прибыль **2 242 500 ₸**.
3. Откройте **Детектор проблем** → **Запустить анализ**. Для периода по умолчанию
   будут найдены рост расходов на упаковку, падение маржи кофе и возможный дубликат.
4. Откройте каждый сигнал: сравнение, формула, исходные файлы/строки, рекомендация
   и условия сценарной оценки. Сигналы также отображаются в обзоре.
5. Новый импорт помечает сохранённый анализ устаревшим. Повторный анализ обновляет
   сигналы выбранного периода с прежними ID, не затрагивая другие периоды/бизнесы.

Расходы на упаковку: **30 000 → 46 500 ₸, +55%**. Маржа кофе:
**62,50% → 25,00%, −37,50 п.п.**. Две одинаковые записи упаковки на 01.10.2026
имеют разные исходные строки и требуют проверки документов. Сценарные оценки
16 500 и 337 500 ₸ могут пересекаться и не суммируются. Они не являются
доказанным ущербом или гарантированной экономией.

## Данные и точность

Модели: Business, Product, ImportBatch, Sale, Expense, Insight, AnalysisRun,
User, BusinessMembership, UserSession и AccountBootstrap.
Каждый запрос ограничен бизнесом; составные внешние ключи запрещают связывать
продажи и расходы с чужими товарами/импортами. SQLite включает внешние ключи и
транзакции; изменения и подтверждение импорта атомарны.

SQLite хранит деньги целыми сотыми долями, количество — целыми тысячными.
SQLAlchemy возвращает Python Decimal. Финансовые расчёты выполняются в Python:
каждая строка округляется до копеек half-away-from-zero, затем суммируется.
Числа не преобразуются в float для хранения или расчётов. API передаёт суммы
десятичными строками; в интерфейсе Number используется только для графиков.

`record_type=return` уменьшает продажи/себестоимость/количество;
`record_type=refund` уменьшает расходы. Суммы во входных файлах положительные.
Скидки учитываются в фактической цене продажи. Расходы представляют операционные
затраты; себестоимость товаров уже учитывается в продажах. Налоги не выводятся
из отсутствующих данных.

Отсутствующая себестоимость делает прибыль и маржу недоступными. Отсутствующие
дни не считаются нулевыми продажами. Правила показывают статус достаточности
данных, окна сравнения и пороги. См. [реализацию требований](REQUIREMENTS.md).

## Импорт CSV и XLSX

1. Создайте бизнес в **Мой бизнес** или `POST /api/v1/businesses`.
2. На странице импорта выберите тип и файл; **Проверить файл** выполняет
   `/api/v1/imports/preview` без сохранения финансовых записей.
3. Исправьте ошибки по строкам/колонкам. **Подтвердить импорт** отправляет тот же
   файл с preview_token в `/api/v1/imports/confirm`. Токен действует 15 минут.
4. Повторный файл или нормализованное содержимое не создают повторный импорт.
   Перестановка строк и пробелы не обходят эту защиту; одинаковые строки внутри
   файла сохраняются для проверки возможных дублей платежей.

CSV: UTF-8, разделитель запятая, дата `YYYY-MM-DD`. XLSX: один лист с теми же
заголовками, без формул. Формулы с кешированными значениями также отклоняются.

| Тип | Колонки |
| --- | --- |
| sales | date,product_id,product_name,quantity,unit_price,unit_cost |
| expenses | date,category,description,amount |
| products | product_id,name; необязательная category |

Продажи/расходы принимают необязательную record_type. unit_cost и description
можно оставить пустыми. Товары создаются из продаж; импорт товаров обновляет их
названия/категории. Неизвестные и повторные заголовки отклоняются.

Лимиты: 10 МБ, 20 000 строк, 32 колонки, 50 МБ распакованного XLSX и 100 ошибок
в ответе. Шаблоны доступны в интерфейсе и `demo_data/`.

## API и рекомендации

| Endpoint | Результат |
| --- | --- |
| GET /api/v1/health | Готовность сервера/БД |
| POST /api/v1/auth/register, /api/v1/auth/login | Регистрация и вход через cookie сеанса |
| GET /api/v1/auth/me | Текущий аккаунт и роли его бизнесов |
| POST /api/v1/auth/logout, /api/v1/auth/password | Выход и смена пароля |
| /api/v1/businesses/{id}/members | Управление командой владельцем: GET, POST, PATCH/DELETE участника |
| POST /api/v1/demo/load | Повторяемое демо |
| GET /api/v1/dashboard/summary | KPI |
| GET /api/v1/analytics/revenue | Дневная выручка |
| GET /api/v1/analytics/expenses | Расходы по категориям |
| GET /api/v1/analytics/products | Прибыльность товаров |
| GET /api/v1/analytics/comparison | Два периода, изменения KPI, товаров и категорий расходов |
| GET /api/v1/analytics/forecast | Дневной прогноз, сценарий, базовые итоги и проверка на истории |
| POST /api/v1/analysis/run | Анализ и статусы пяти правил |
| GET /api/v1/insights | Сигналы, severity/type и пагинация |
| GET /api/v1/insights/{id} | Доказательства и рекомендация |
| GET /api/v1/advisor/status | Наличие конфигурации LLM без раскрытия ключа |
| POST /api/v1/advisor/chat | Советник по бизнесу/периоду; история, факты и fallback |
| GET /api/v1/reports/pdf | PDF с KPI, сигналами и источниками |

Бизнес-запросы требуют входа и доступа к выбранному бизнесу; сервер проверяет роль.
Владелец управляет командой, аналитик импортирует и запускает анализ, наблюдатель
читает показатели, использует советника и скачивает PDF. Полная матрица прав и
примеры API — в [гайде аккаунтов](docs/ACCOUNTS_AND_LANGUAGE_GUIDE.md).
Аналитика и сигналы требуют business_id, принимают date_from/date_to включительно.
Период 1–366 дней; по умолчанию 90 дней до последней подтверждённой даты данных
(в сравнении периодов — 30 дней и предыдущее окно той же длины).
POST анализа принимает те же поля в JSON. Описание правил и сценарий приёмки
находятся в `REQUIREMENTS.md`; независимые ожидаемые результаты — в `demo_data/`.

Рекомендации на русском и казахском доступны в шаблонном режиме, через Gemini и OpenAI Responses API.
Страница **AI-советник** поддерживает беседу, а карточка сигнала — отдельное
пояснение. Внешняя отправка требует включённого LLM, серверного ключа и отметки
разрешения в интерфейсе. Числа берутся только из проверенных фактов backend.
При отсутствии ключа, ошибке API или непроверяемом ответе используется шаблон.
История временная и не хранится в БД; по умолчанию backend передаёт четыре сообщения
до 1200 символов каждое и до трёх главных сигналов. Лимит ответа — 600 токенов.
Проверенные одинаковые запросы кешируются в памяти на 10 минут; ошибки квоты
включают паузу без автоматических повторов. Ответ помечается как сохранённый,
если нового внешнего запроса не было.

Для бесплатного режима выбран Gemini 3.5 Flash-Lite; нужен отдельный ключ
Google AI Studio и доступ к Free tier в аккаунте. В `.env.example` указан этот
вариант. OpenAI остаётся резервом с `gpt-4.1-nano`; резерв включается вручную,
автоматического платного переключения нет. Отметка разрешения относится к
конкретному провайдеру и сбрасывается при смене провайдера или модели.

**Скачать PDF** формирует локальный отчёт за выбранный период без вызова LLM.
Пример: [отчёт кафе Тараза](output/pdf/taraz-report.pdf). Полная инструкция:
[LLM, чат и PDF](docs/LLM_ADVISOR_GUIDE.md). Язык отчёта соответствует выбранному
языку интерфейса; названия и категории из исходных файлов сохраняются.
Основной сценарий запуска — локальный сервис. Для публикации через HTTPS настройте
защищённую cookie и разрешённый адрес интерфейса по гайду аккаунтов.

Контракт и типы обновляются вместе:

```powershell
backend/.venv/Scripts/python.exe backend/scripts/export_openapi.py
npm.cmd --prefix frontend run generate:api
```

## Проверки

Все тесты БД используют изолированную SQLite и не требуют TEST_DATABASE_URL.
Они не обращаются к рабочему `backend/profitleak.db`.

```powershell
backend/.venv/Scripts/python.exe -m pytest backend/tests -q
backend/.venv/Scripts/python.exe -m ruff check backend
backend/.venv/Scripts/python.exe -m alembic -c backend/alembic.ini check
backend/.venv/Scripts/python.exe backend/scripts/export_openapi.py --check
npm.cmd --prefix frontend test
npm.cmd --prefix frontend run build
```

Тесты проверяют независимые KPI/демосигналы, точность больших сумм, возвращённые
операции, отсутствующие данные, малые выборки, доказательства, изоляцию бизнесов,
повторный импорт/анализ, устаревшие результаты, откат и соответствие миграций.
Также проверяются протоколы OpenAI/Gemini на HTTP-заглушках, согласие на внешнюю отправку,
подстановка точных фактов, отказ от выдуманных чисел, ошибки ключа/квоты/сети и
кириллица, KPI, источники и состояния анализа в PDF. Тесты не расходуют API-квоту.

Проверка этапа 14.10.2026: 142 теста backend и 3 теста frontend прошли, сборка,
Ruff, контракт OpenAPI и Alembic check успешны. Локальные HTTP-запросы к чату
и PDF вернули 200; все четыре страницы демо-отчёта проверены визуально.
Реальный вызов OpenAI не проверен без пользовательского ключа. Автоматическая
проверка интерфейса в браузере была недоступна из-за сбоя инструмента Codex.
