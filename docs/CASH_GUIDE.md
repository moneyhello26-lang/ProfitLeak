# Деньги и платежи

Раздел `/cash` работает локально с SQLite и доступен из главного меню на русском
и казахском. Он добавлен после исходного MVP: счета, движение денег, обязательства,
платёжный календарь, прогноз остатка и месячный бюджет расходов.

## Начало работы

1. Создайте счёт или кассу. Укажите остаток **на начало дня** выбранной даты.
   Для загрузки старой выписки дата открытия должна быть не позже первой операции.
   Валюта всех счетов — KZT; отрицательный начальный остаток допускается.
2. Добавьте поступления и списания вручную или импортируйте выписку. Переводы
   записываются одной операцией с указанием двух своих счетов: общий остаток
   бизнеса не меняется, в доходы и расходы ДДС перевод не включается.
3. В календаре создайте ожидаемые поступления/списания. Они не меняют фактические
   остатки до отметки **Оплатить**. Укажите реальную дату оплаты; повторная отметка
   не создаёт второе списание. Ненужный плановый платёж можно отменить.
4. Для еженедельных и ежемесячных платежей после оплаты создаётся следующий
   экземпляр. День месяца сохраняется: 31 января → 28 февраля → 31 марта.
   В прогноз входят только уже созданные экземпляры, а не бесконечная серия.
5. Задайте бюджет по категории на месяц. Повторное сохранение той же категории
   и месяца обновляет лимит. Факт — все денежные списания этой категории за весь
   месяц начала выбранного периода, даже если фильтр охватывает только несколько
   дней. Отрицательный остаток бюджета показывает превышение лимита.

## ДДС и прогноз

Фактический остаток на конец = остаток на начало + начальные остатки счетов,
открытых внутри периода + поступления − списания. Переводы сохраняют общий итог.
Счета, открывающиеся после конца периода, ещё не добавляют начальный остаток.
Денежные суммы хранятся и считаются точно, передаются API десятичными строками.

Прогноз по дням учитывает записанные операции и ожидаемые платежи. Просроченные
платежи включаются в первый день выбранного периода. Дефицит проверяется отдельно
на каждом счёте: положительный общий остаток не скрывает нехватку денег на счёте
оплаты. Состояние показано на конец дня; внутридневная последовательность операций
и ещё не записанные обязательства неизвестны. Это расчёт по введённым данным,
а не гарантия отсутствия кассового разрыва.

Продажи и расходы из основного раздела учитывают прибыль, а не факт оплаты.
Поэтому они **не копируются автоматически** в денежный журнал. Импорт выписки
также не создаёт повторных продаж и расходов в обзоре прибыли.
Это управленческий денежный журнал, не бухгалтерский баланс или налоговый учёт.

## Обмен с банками и 1С

Выбран файловый обмен CSV/XLSX без ключей и внешних сервисов. Используйте
`frontend/public/templates/cash_statement.csv` или кнопку **Скачать шаблон выписки**.
Произвольные исходные форматы банков и конфигураций 1С автоматически не распознаются:
перед загрузкой экспорт нужно привести к указанным колонкам.

| Колонка | Значение |
| --- | --- |
| date | Дата операции, YYYY-MM-DD |
| kind | income — поступление, expense — списание |
| amount | Положительная сумма, максимум два знака после точки |
| category | Категория, одинаковое написание для сопоставления с бюджетом |
| description | Описание, может быть пустым |
| reference | Стабильный уникальный номер операции из источника |

CSV: UTF-8, разделитель — запятая. XLSX: один лист, заголовки в первой строке,
формулы запрещены, включая формулы с кешированными результатами. Лимиты: 10 МБ,
20 000 строк, 32 колонки, ограничение распакованного XLSX. Сначала предпросмотр,
затем подтверждение того же файла для того же счёта по подписанному токену.
Ошибка любой строки запрещает подтверждение всего файла. Номер операции уникален
в пределах счёта; переименование файла и перестановка строк не обходят защиту.
Если банк не выдаёт номер, сформируйте стабильный идентификатор до загрузки
и сохраняйте его при последующих выгрузках.

Переводы между собственными счетами добавляйте вручную одной операцией и исключайте
обе стороны такого перевода из импортируемых выписок, иначе они попадут в поступления
и списания. Не импортируйте повторно проведённый вручную платёж без того же номера
операции: система не может сопоставить их по одному лишь описанию.

Прямые API банков, прямое подключение к базе 1С и отправка платежей в банк
в этот файловый обмен не входят. Для них нужны выбранный провайдер, документация,
договор/доступ и отдельная проверка в его среде.

## Права и сохранность

Владелец и аналитик могут добавлять операции, счета, планы, бюджеты и выписки.
Наблюдатель видит отчёты и журнал. Чужие бизнесы и счета недоступны; связи счетов
дополнительно ограничены составными внешними ключами БД. Проведённые операции
не удаляются из интерфейса: ошибку корректируют обратной операцией с описанием.

Миграция `0007` добавляет четыре таблицы и не переписывает старые финансовые
данные. Штатный `start-local.ps1` применяет её перед запуском. Резервная копия
SQLite включает и новый денежный раздел; инструкция — [LOCAL_RELEASE.md](LOCAL_RELEASE.md).
