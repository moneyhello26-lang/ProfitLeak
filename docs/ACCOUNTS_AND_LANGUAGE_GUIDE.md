# Аккаунты, роли и қазақша

## Запуск и первый аккаунт

Запустите из корня проекта в PowerShell:

```powershell
.\start-local.ps1
```

Скрипт применяет миграции SQLite и запускает сайт на `http://127.0.0.1:5173`.
Docker, дополнительные сервисы авторизации и API-ключи не нужны.

1. На странице входа откройте **Регистрация**.
2. Введите имя, email и пароль от 10 до 128 символов. Подтвердите пароль.
3. Первый зарегистрированный аккаунт автоматически получает роль владельца
   бизнесов, созданных до появления системы аккаунтов. Существующие продажи,
   расходы, товары, импорты и анализы сохраняются.
4. Последующие аккаунты начинают без доступа к чужим бизнесам. Они могут создать
   свой бизнес в **Мой бизнес** или попросить владельца добавить их в команду.
5. После регистрации вход выполняется автоматически. В дальнейшем используйте
   email и пароль на вкладке **Вход**. Кнопка выхода находится в верхней панели.

Готовых логинов и общих паролей в проекте нет. Реальные аккаунты и пароли при
обновлении не создавались. Перед миграцией существующей рабочей базы сохранена
локальная резервная копия в `.tmp/backups/`.

## Роли в каждом бизнесе

| Возможность | Владелец | Аналитик | Наблюдатель |
| --- | :---: | :---: | :---: |
| Обзор, товары, сравнение и прогноз | Да | Да | Да |
| Просмотр готовых сигналов и истории импорта | Да | Да | Да |
| Советник и скачивание PDF | Да | Да | Да |
| Проверка и подтверждение импорта | Да | Да | Нет |
| Запуск и обновление анализа | Да | Да | Нет |
| Просмотр списка участников и управление ролями | Да | Нет | Нет |

Роль назначается отдельно для каждого бизнеса. Например, пользователь может
быть владельцем одной компании и наблюдателем другой. Проверка прав выполняется
на сервере при каждом запросе, включая PDF, советник, импорт и отдельные сигналы.
Изменение роли или отзыв доступа вступают в силу без повторного входа.

Любой аккаунт может создать новый собственный бизнес и станет его владельцем.
Загрузка демо создаёт отдельный синтетический бизнес для текущего пользователя;
повторная загрузка не дублирует записи и не открывает доступ к чужим данным.

### Как добавить участника

1. Попросите участника зарегистрироваться на этом же сайте.
2. Выберите нужный бизнес в верхней панели.
3. Откройте **Аккаунт и команда**.
4. Укажите email зарегистрированного пользователя, выберите роль и нажмите
   **Добавить участника**.
5. Изменить роль можно в таблице команды. Для удаления используйте корзину
   и подтвердите отзыв доступа.

Приглашения по email не отправляются: доступ выдаётся существующему аккаунту.
Последнего владельца нельзя удалить или понизить в роли. Чтобы передать управление,
сначала назначьте другого участника владельцем. После этого можно изменить свою роль.

## Язык интерфейса

В верхней панели и на странице входа есть переключатель **RU / ҚАЗ**.
Выбор сохраняется в браузере и применяется к меню, формам, сообщениям, датам,
графикам, сравнению, прогнозу, сигналам, советнику и новым PDF.

Названия ваших бизнесов, товаров, категорий и имена участников не переводятся
автоматически. Исходные CSV/XLSX и машинные заголовки колонок остаются прежними.
Числа рассчитываются как Decimal и не меняются при переключении языка.
У существующих анализов переводится представление; исходные доказательства в БД
не перезаписываются. Временная беседа советника очищается при смене языка.

Для PDF выберите **ҚАЗ**, затем нажмите кнопку скачивания на странице обзора,
товаров, детектора или советника. Шрифт поддерживает **Ә Ғ Қ Ң Ө Ұ Ү Һ І**.
Для ответа LLM на казахском язык передаётся в инструкциях провайдеру;
шаблонный советник также работает на казахском без внешнего API.

Қысқаша: **ҚАЗ** таңдаңыз → **Тіркелу** немесе **Кіру** → бизнесті таңдаңыз.
**Тіркелгі және команда** бөлімінде иесі тіркелген пайдаланушыларды қосып,
оларға **Иесі**, **Талдаушы** немесе **Бақылаушы** рөлін бере алады.

## Сеансы и настройки

Пароли хранятся в виде хеша scrypt с отдельной случайной солью. Случайный токен
сеанса находится в HttpOnly-cookie; база хранит его SHA-256-хеш. Выход удаляет
текущий сеанс. В **Аккаунт и команда** можно сменить пароль: после этого все
сеансы аккаунта завершаются. Хеширование и управление сеансами опираются на
[OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)
и [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).

В `.env.example` добавлены:

```dotenv
SESSION_COOKIE_SECURE=false
SESSION_TTL_HOURS=168
```

`false` подходит для локального HTTP. При работе через HTTPS укажите
`SESSION_COOKIE_SECURE=true`. Срок сеанса по умолчанию — 7 дней; настройка принимает
1–720 часов. `CORS_ORIGINS` должен содержать фактический адрес интерфейса:
изменяющие запросы с посторонних сайтов отклоняются.

Локальный запуск использует один процесс API. Ограничение попыток входа хранится
в памяти этого процесса: 10 попыток на email и 30 на IP за 10 минут. Восстановление
пароля через почту и подтверждение email в текущую реализацию не входят.

## API

| Запрос | Назначение |
| --- | --- |
| `POST /api/v1/auth/register` | `{email, password, full_name}` — регистрация и вход |
| `POST /api/v1/auth/login` | `{email, password}` — вход |
| `GET /api/v1/auth/me` | Текущий пользователь и роли его бизнесов |
| `POST /api/v1/auth/logout` | Завершить текущий сеанс, ответ 204 |
| `POST /api/v1/auth/password` | `{current_password, new_password}`, завершить все сеансы |
| `GET /api/v1/businesses/{id}/members` | Участники, только владелец |
| `POST /api/v1/businesses/{id}/members` | `{email, role}` — добавить участника |
| `PATCH /api/v1/businesses/{id}/members/{user_id}` | `{role}` — изменить роль |
| `DELETE /api/v1/businesses/{id}/members/{user_id}` | Отозвать доступ, ответ 204 |

Значения ролей API: `owner`, `analyst`, `viewer`. Все бизнес-запросы требуют cookie
сеанса. Для браузерного fetch используйте `credentials: 'include'`, для скрипта —
клиент с сохранением cookie. Токен не возвращается в JSON и не читается JavaScript.
`401` означает отсутствие или истечение сеанса, `403` — недостаток прав,
`404` — отсутствующий или недоступный бизнес, `409` — конфликт участника/владельца.
`GET /api/v1/health` остаётся общедоступным.

Для языка передавайте `Accept-Language: kk` или `Accept-Language: ru`.
Ответ содержит `Content-Language`; схема, enum-коды и формат денежных строк не меняются.
Полный контракт доступен на `http://127.0.0.1:8000/docs`.
