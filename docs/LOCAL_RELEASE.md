# Локальный выпуск ProfitLeak

Основной вариант после уточнения 17 октября 2026: проект запускается на вашем
компьютере. Docker, Render, Neon, PostgreSQL, домен и облачные аккаунты не нужны.
База SQLite, аккаунты, импорты, анализы, статусы и заметки хранятся локально.

Добавлен раздел **Деньги и платежи**: счета, денежные операции, календарь,
бюджет и импорт выписок. [Инструкция и границы файлового обмена](CASH_GUIDE.md).
Миграция `0007` применяется автоматически перед запуском; существующие записи
продаж, расходов, аккаунтов и анализов не переписываются.

## Запуск

Из корня проекта в PowerShell:

```powershell
.\start-local.ps1
```

Откройте **http://127.0.0.1:5173**. Это один процесс FastAPI, который обслуживает
API и готовый интерфейс React. Отдельный Vite-сервер не запускается. Ctrl+C
останавливает приложение; данные остаются в `backend/profitleak.db`.

Если порт занят, остановите прежний экземпляр или выберите другой порт:

```powershell
.\start-local.ps1 -Port 8017
```

Адрес тогда `http://127.0.0.1:8017`. Приложение слушает только этот компьютер.
Локальный запуск принудительно выбирает SQLite, отключает внешний LLM и его
API-ключи для текущего процесса, даже если в старом `.env` были облачные настройки.
Сам `.env` не переписывается. Советник отвечает локальными шаблонами; импорт,
сравнение, прогноз, детектор и PDF работают без внешнего API.

## Установка из архива на другом компьютере

Распакуйте архив в новую папку. Нужен Python 3.11+; не переносите чужую `.venv`.
В архив локального выпуска включена готовая `frontend/dist`, поэтому Node.js
для обычного запуска из этого архива не нужен.

```powershell
python -m venv backend/.venv
backend/.venv/Scripts/python.exe -m pip install './backend'
.\start-local.ps1
```

При первой установке pip скачивает зависимости. После установки для обычной
работы проекта облачные сервисы и интернет не требуются. Если PowerShell
блокирует локальный скрипт:

```powershell
powershell -ExecutionPolicy Bypass -File .\start-local.ps1
```

Если взяты исходники Git или изменён интерфейс, нужны Node.js 22.18+ и новая сборка:

```powershell
npm.cmd --prefix frontend ci
npm.cmd --prefix frontend run build
```

`start.ps1` оставлен для разработки с отдельными API/Vite. Он читает остальные
настройки `.env`; для готовой версии без облака используйте `start-local.ps1`.

## Первый вход и проверка функций

1. Зарегистрируйте свой аккаунт. Готовых общих паролей нет. Первый аккаунт
   получает ранее созданные локальные бизнесы; при новой установке база пустая.
2. Откройте демо или создайте бизнес и импортируйте CSV/XLSX из `demo_data/`
   либо `output/ProfitLeak_import_data/`. Выберите правильный тип: продажи,
   расходы или товары. Сначала проверьте файл, затем подтвердите импорт.
3. Проверьте обзор, товары, сравнение и прогноз. В демо кафе выручка за все
   90 дней — 5 454 000 ₸. Прогноз требует достаточной истории.
4. Запустите анализ; откройте доказательства, сохраните статус и заметку.
   Повторите анализ того же периода: совпавшие сигналы сохраняют отметки.
5. Скачайте PDF, переключите **RU / ҚАЗ** и проверьте локальный советник.
6. Для команды участник сначала регистрируется на этом же экземпляре сайта.
   Владелец добавляет его email в **Аккаунт и команда**. Права трёх ролей
   описаны в [гайде аккаунтов](ACCOUNTS_AND_LANGUAGE_GUIDE.md).
7. Остановите и снова запустите приложение. Войдите своим аккаунтом: бизнес,
   импорты, анализ и заметка должны сохраниться.

Новая установка и ранее опубликованная версия имеют разные базы. Облачные
данные автоматически не скачиваются и для локального запуска не требуются.

## Резервная копия

Команды ниже выполняются из корня проекта. Имя копии должно быть новым:

```powershell
New-Item -ItemType Directory -Force backups | Out-Null
backend/.venv/Scripts/python.exe backend/scripts/sqlite_snapshot.py backup backend/profitleak.db backups/profitleak-20261017.db
```

Утилита делает согласованную SQLite-копию, проверяет целостность и внешние ключи.
Существующий файл назначения не перезаписывается. Копия содержит аккаунты,
данные и сеансы; храните её отдельно от исходников и архива передачи.

## Проверка восстановления

Остановите приложение. Восстановите копию в новый файл и откройте именно его:

```powershell
backend/.venv/Scripts/python.exe backend/scripts/sqlite_snapshot.py restore backups/profitleak-20261017.db backend/profitleak-restored.db
.\start-local.ps1 -Database backend/profitleak-restored.db
```

Проверьте вход, импортированные суммы, сигналы и заметки. Основной файл
`backend/profitleak.db` при этом сохраняется. Для дальнейшей работы с восстановленной
версией запускайте с тем же параметром `-Database`.

## Проверки исходников

Финальный архив: `output/ProfitLeak_local_2026-10-17-final.zip`.
Он не содержит базы, паролей, `.env`, Python-окружения и `node_modules`.
Создание архива из актуального рабочего дерева с готовой сборкой:

```powershell
backend/.venv/Scripts/python.exe backend/scripts/package_local.py
backend/.venv/Scripts/python.exe backend/scripts/package_local.py --verify
```

Утилита откажется перезаписывать существующий ZIP. Для нового снимка задайте
другое имя через `--output`. В ZIP включены исходники, сборка интерфейса,
инструкции и `LOCAL_RELEASE_MANIFEST.json` с SHA-256 каждого файла и исходным
коммитом. Проверяются целостность, контрольные суммы и assets из index.html.

Для проверки распаковки, реального запуска, перезапуска и восстановления на
отдельных тестовых базах (нужны установленные backend-зависимости):

```powershell
backend/.venv/Scripts/python.exe backend/scripts/verify_local_release.py output/ProfitLeak_local_2026-10-17-final.zip
```

Результаты сохраняются в новой папке `.tmp/final release .../`. Рабочая база
не открывается; синтетические данные создаются только внутри этой папки.
Утилита не выполняет браузерные загрузки файлов и не вызывает внешние LLM.

Для тестов установите дополнительные зависимости разработки:

```powershell
backend/.venv/Scripts/python.exe -m pip install -e './backend[dev]'
backend/.venv/Scripts/python.exe -m pytest backend/tests -q
backend/.venv/Scripts/python.exe -m ruff check backend
backend/.venv/Scripts/python.exe backend/scripts/export_openapi.py --check
npm.cmd --prefix frontend test
npm.cmd --prefix frontend run build
```

Тесты используют отдельные базы и не очищают рабочую SQLite. Актуальные
результаты выпуска и пределы ручной проверки записаны в [HANDOFF.md](../HANDOFF.md).
